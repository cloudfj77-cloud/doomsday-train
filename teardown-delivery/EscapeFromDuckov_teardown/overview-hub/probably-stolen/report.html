最重要的发现：
  • 代码即数据。物品、顾客、事件、升级、特性全部硬编码在 C# 里（Add("id", () => Factory())），没有外部配置表，所以反编译就能拿到完整数值。

日循环、周循环、整局循环三层嵌套。没有实时倒计时，节奏完全由“顾客队列 + 星期几”驱动。

02经济系统：指数房租 vs 线性收入

玩家的收入线性增长并带有阶梯，房租却每周复利上涨。中后期必须靠“质变”（升级、产业线、违禁品、买断）才能脱离压力。

房租曲线与按揭“锁价”

轻松 ×1.025/周普通 ×1.05/周困难 / 挑战 ×1.10/周 普通按揭周供 930（12 周）困难按揭周供 1616（16 周）

起租 200（部分开局为 240 或 250），每 7 天交一次。不管付没付都会涨，每周 rent = (int)(rent × 倍率)。困难难度第 26 周达到约 2100/周，大约第 23 周起房租会超过按揭周供，等于在鼓励玩家中期锁定按揭。

统一定价公式

售价 = round( ((基础价 × (1 + 内在品质%) + 容器价) × (1 + Σ市场修正%) + 子物品) × Π最终系数 )
  · 内在品质：纯度 / 品相 / 真伪……
  · 市场修正（先求和、再一次相乘）：零售加价 15%、事件 ±%、违禁品 +35 / 70 / 100 / 150%、游客税 +15%……
  · 最终系数：议价折扣或加价

来源：GameItem.ComposeStagedValue（GameItem.cs:1733）、ItemFeatureList。市场修正之所以采用加法，是为了避免多个修正叠乘后价格爆炸。

04风险与治安：延迟引爆的罪证系统

游戏里的“突袭”并不是一个战斗系统，而是由盘查、罪证累积、判决警官、晨间上门、炸弹、派系行动合成的风险管理玩法。

赃物“热度”就是被发现的概率

按基础价，初始热度为 25 / 50 / 75 / 100。每晚热度 −18，降到 0 就洗白。收赃时自动打 10% 到 25% 的折扣。

藏匿手段：走私暗格、锁住的容器、海报后的 2×2 暗格都不会被查。

通缉犯：举报正确得赏金且治安 +5；误报治安 −8、罚 50；不举报没有任何数值惩罚，要不要举报完全交给玩家的良心。

05物品与产业线：标签值 vs 实际值

整个鉴定和造假玩法建立在一个数据结构上：每个物品特征同时存“标签上写的”和“实际的”两个值。

① 收货鉴定

玩家用放大镜、试纸、扫描仪揭穿供货方虚报的标签值，按实际值压价。目检指出瑕疵后收货价再 −15%；指错了，该派系声望 −2。

② 出货造假

贴标机改写标签值：幽灵水标成纯水，价格 ×2.6；失效注射器标成真品，价格 ×20。

③ 被顾客识破

识破能力按派系写死：黑市和治安部自带试纸，游客和上层区认不出假烟。被识破时派系声望 −4。

造假的主要惩罚不是当场被抓，而是延迟累积的犯罪账本：卖出错标的水按“毫升 × 权重”累计，每晚只减 5，累计到 2500 就记罪并收到威胁信。一瓶幽灵水标成纯水就会超线；卖给游客则不计入。

物品数据模型与网格

  • GameItem 本身字段很少，只有 unitValue、unitCount 和网格形状。真伪、纯度、耐久、热度、违禁等级都存在字符串键值包 TagSystem（约 845 个键）和 ItemFeature 里。
  • 行为是约 50 个委托钩子，由约 100 个 *Helper.InitXxx(item) 把函数挂上去“组装”。多个函数挂在同一钩子上时，结果按与 / 或 / 最大 / 最小合并。
  • 网格形状由精灵图的透明度逐格采样自动生成，可以旋转、翻转、层层嵌套。店铺分区：主库存 24×10、前后台各 18×4、展柜 7×5、海报后暗格 2×2。
  • 位置也是玩法：能量阵列和电鳗给相邻设备供电，模组看相邻节点给加成。
  • 价格分布：中位数 40 cr，最高 15000（超科技涡轮增压器）。

付款时先扣恩惠，不够再扣现金。恩惠来自下层声望（每点 40）、交易抽成和订阅费返还。

形成“花钱订阅 → 返还恩惠 → 买下一个升级”的循环。

终局回收开局取舍

买断店铺后可以接触超科技走私贩，他卖“心智重编程器”，可以在局中删除开局选的负面特性，把开局时的取舍放到终局去回收。

外围玩法

  • 夜间外出：每晚 1 次，3 个地点（垃圾场、配给站、杰克逊博士），7 个原版事件按星期排期。代价是第二天少 1 个顾客。
  • 彩票 / 刮刮乐：返还率约 57% 和 59%（刮刮乐按 40 万次模拟），长期是负期望，属于氛围玩法。
  • 配给站：食品券按固定价格买货，补货量随市场短缺或过剩变化，是一个套利窗口。
  • 电话供货商：6 个号码，累计消费达到门槛后才能订大单；入股后按固定星期收到分红货物。

值得重点关注：Mod 安全体系（约 1 万行）

① 能力声明

manifest.xml 必须声明文件、网络、反射、Steam 等 8 类能力；纯数据 mod 也必须带一个实现 IMod 的 DLL。

② IL 静态扫描

用 Cecil 读取 mod 的 IL：未声明的能力需要玩家确认；窃密特征、启动进程、工坊发布、自带 Harmony、高熵资源一律直接拒绝。

③ 信任链

用 SHA-256 给 manifest 和 DLL 做指纹，本机保存批准记录；mod 更新后只要能力没有扩大就自动放行。另有 RSA 签名的远程信任列表、全局停用开关和防回滚。

④ 运行时熔断

Harmony 拦截 Steam 账号类 API 和 Process.Start，触发即永久停用该 mod 版本；每 10 秒自检一次守卫补丁是否还在。

其他工程要点

  • 存档：ES3 每个存档槽两个键，约 160 个字段；物品只存 ID 和状态，读档时重新跑工厂函数，所以行为不进存档。按天保留历史快照，有完整性检查、损坏隔离、IO 重试。
  • UI 四代并存：整数像素 PixelElement、47 个传统 *UIManager、由代码生成预制体的 “UI3”，以及链式 CustomUIBuilder（mod、设置、调试面板共用）。
  • 本地化：代码里内置英文兜底，表里缺 key 就显示英文；有性别和敬语标记；按 Unicode 区间逐串切换中日韩字体。
  • 开发工具：游戏目录放一个 dev.txt 就能开启 F9 调试面板（里面有一组 Marketing 按钮，专门为录预告片摆场景）；卡顿看门狗；游戏内纸张文档编辑器（可导出成 C# 代码）。埋了 19 个分析事件，但发行版用常量开关全部关掉了。
  • 技术债：PlayerStore 有 4213 行，被引用 3773 次；原型代码还留在主循环里；29 处 [RuntimeInitializeOnLoadMethod] 写在实例方法上，不会生效；26 个空 catch。

09设计洞察：为什么能爆

1. 每个顾客都是一场“能算期望、但只能押一次”的赌局

信息不对称（身份、真伪、罪犯）加上公开的概率（议价 tooltip 直接显示成功率）。玩家能算期望，却只能下一次注，每一次举报、敲诈、加价都带着张力。

2. 双账本互相牵制

现金账（看得见）对上声望账和罪证账（延迟兑现）。贪心的收益是即时的，代价是延迟的，这正是“再来一天”的心理钩子。

3. 一套底层，多条产业线

标签值与实际值的双值结构、夜间结算、三段定价、按派系写死的识破能力、衰减式犯罪账本，这一套底层被复用到 8 条产业线。每条线只换原料、工艺和品质变量，内容产出效率极高。

4. 压力曲线由数学保证

指数房租对上线性收入，加上“交租日必来商人”的流动性阀门，以及“中期锁定按揭”的明确出口，玩家永远有一个看得见的目标。

5. 道德留白

不举报通缉犯没有数值惩罚，熟人剧情把交易和背叛绑在一起，玩家自己选择要当什么样的店主。这一点继承了 Papers, Please 的核心魅力。

6. 题材包装的胜利

机制框架基本延续前作，换上赛博朋克加灰色地带交易的包装之后，同时在线从 28 人涨到 16 万人。好的系统需要一个让人一眼就想玩的“幻想”。

可借鉴的短板：升级树太浅、互斥取舍太弱，钱够了就能全买，后期策略深度不足；夜间外出这条线到后期没有任何成长空间。还没做完的远征和雇员系统正好是补这块的，大概率会出现在后续更新里。
