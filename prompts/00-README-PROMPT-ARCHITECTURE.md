# 《鸭科夫黑店：暗账与撤离》(Duckov Pawnshop) —— 融合游戏 Prompt 工程总览

> **融合母体**：
> - **母体 A**：《可能是偷的》(Probably Stolen) —— 24.5 万行 C# 拆解全量（队列即时钟、双值物品真伪/贴假标、公开概率 6 动作议价、声望与罪证双暗账、复利房租与按揭锁价、王尔德恩惠升级网、夜间结算产业机器，以及原作未完成的 `InRaid() => false` 远征遗憾）。
> - **母体 B**：《逃离鸭科夫》(Escape from Duckov) —— 15 万行 C# + 3D 场景拆解全量（`Item` 树 + `Stat/Modifier` 万物同源、动作优先级抢占、`2/(A-P+2)` 护甲穿透与爆头伤害管线、`55°俯仰 + 20°FOV` 微缩模型俯视镜头、AI 视锥+听觉广播、昼夜天气元素联动、`Tag×品质` 掉落与按稀有度递增读条时长、倒计时撤离圈）。
> - **运行底座**：天工引擎 (`@forgeax/engine@0.4.19`) + 造化插件 (`zaohua-platform-sdk`)。

## 1. 为什么这两款游戏是天作之合？（核心融合公理）

在《可能是偷的》反编译源码考古中，最震撼的发现是 `GameMaster.InRaid() => false` 与未接入口的 `Expedition`（远征）系统——原作前身曾尝试做“外出突袭”，最终降维成了每晚点一下地图图标的静态“夜间外出（代价：次日 -1 随机顾客）”；导致游戏到了中后期夜间玩法缺乏成长空间。

与此同时，《逃离鸭科夫》拥有小团队极致的 **3D 低模俯视搜打撤体验**，但回到基地后的商店买卖是传统的固定倍率面板，缺少“鉴宝、造假、博弈顾客心理、应对治安盘查、周旋多派系暗账”的经营深度。

**《鸭科夫黑店》用一条严丝合缝的闭环把两者焊死成一个有机生命体**：

```text
[白天 · 地堡卷帘门黑店 (Probably Stolen 核)]
  拉起卷帘门 → 生成当日顾客栈（拾荒鸭/阔佬/乌鸦黑市/治安官/剧情客）
  → 紫外灯/试纸/频谱仪验货压价 · 贴标机改写标签造假 · 6动作公开概率议价
  → 治安盘查员突击检查（把高热度赃物/违禁品塞进海报后 2×2 暗格！）
  → 拉下卷帘门打烊 → 后屋机器（净水/化学提纯/3D枪械打印/解码器）装填原料
        │
        ├── 选择 A：直接睡觉 → 机器结算 + 赃物热度 -18 + 明日满客流
        │
        └── 选择 B：亲自夜袭封锁区！(激活 InRaid() => true · Escape from Duckov 核)
              穿戴头盔护甲 + 改装枪械配件 → 潜入 3D 俯视战区（零号区/码头暗仓/农场镇/J-Lab）
              → 视锥迷雾潜行 & 枪战（护甲 2/(A-P+2)、爆头、翻滚、流血包扎、天气增减伤）
              → 搜刮物资箱（按稀有度递增读条时长，心跳开箱！）
              → 站进绿色烟雾撤离圈倒计时撤离！（代价：熬夜出击明日 -1 随机客；阵亡仅保安全箱）
              → 战利品带回黑店：自用升级武备 / 投喂后屋机器提纯 / 贴假标翻 3~10 倍卖给阔佬与游客！
```

## 3. Prompt 工程套件目录与使用方式

本目录采用 **Context-Layered Prompt Engineering（分层上下文工程）** 设计，杜绝单条万字模糊 Prompt 导致的幻觉与数值崩塌：

| 序号 | 文件 | 职责与适用阶段 |
|---|---|---|
| `01` | [`01-SYSTEM-ORCHESTRATOR.prompt.md`](./01-SYSTEM-ORCHESTRATOR.prompt.md) | **总控 System Prompt**：角色设定、天工引擎 + 造化插件硬约束、双包融合架构原则、代码与美术规范 |
| `02` | [`02-DATA-AND-FORMULA-CONTRACT.prompt.md`](./02-DATA-AND-FORMULA-CONTRACT.prompt.md) | **数学公式与 Schema 契约 Prompt**：所有常量、概率、伤害、房租、议价、暗账与统一 TypeScript 接口定义（SSOT） |

| `05` | [`05-CONTENT-NARRATIVE-AND-ASSET-GEN.prompt.md`](./05-CONTENT-NARRATIVE-AND-ASSET-GEN.prompt.md) | **叙事、物品库与 AI 资产生成 Prompt 库**：跨昼夜 5 条主线任务、物品图鉴表、净室美术/音效生成标准提示词 |

### 标准喂入顺序（给任意 AI Coding Agent 使用时）
1. **建项初始化**：将 `01` + `02` 一起作为首轮上下文喂入，让 Agent 先落盘纯数据与数学契约层（零 UI/零渲染依赖，100% 可单测）。
2. **双核并行或串行实现**：依次喂入 `03`（3D 搜打撤层）与 `04`（黑店经营 UI 层），两者仅通过统一的 `GameStore` 状态机交换战利品、装备、现金与日期推进。
3. **内容填充与打磨**：喂入 `05` 扩充武器、违禁品、剧情熟客与合成音效。
4. **终验交付**：喂入 `06` 跑通类型检查、单测、自动化场景与造化插件预览。
